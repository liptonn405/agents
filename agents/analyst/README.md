# AnalystAgent

**Ответственный:** разработчик №1.

Агент получает артефакт от ArchitectAgent, проверяет его выполнимость по
реальному коду Miminet и формирует строгое задание для CoderAgent. Код агент
не изменяет, тесты не запускает и ничего не коммитит.

## Пайплайн

```text
ArchitectArtifact
      ↓
AnalystAgent: Code RAG + проверка требований и путей
      ↓
CoderTask 1.0  +  AnalystReport (sidecar)
      ↓
CoderAgent
```

`CoderTask` совместим со строгой схемой `agents/developer/coder_agent/contracts.py`
(версия `1.0`). `AnalystReport` хранит трассировку требований, тест-план, риски
и открытые вопросы; он не передаётся CoderAgent как часть задания.

## Входной артефакт

Основной формат — **Markdown**. Пример: `examples/architect_artifact.md`.

```markdown
# Артефакт Архитектора

artifact_id: arch-001

## Цель

Добавить в профиль пользователя статистику по созданным сетям.

## Требования

- Показывать количество сетей пользователя.
- Показывать дату последней созданной сети.

## Критерии готовности

- Статистика видна на странице профиля.

## Ограничения

- Не дублировать запросы к БД.
```

Поддерживаемые разделы: «Цель», «Требования», «Критерии готовности»,
«Ограничения», «Вне рамок», «Затронутые компоненты», «Контекст», «Issue».
`artifact_id` можно указать строкой `artifact_id: ...`. Если разделов нет,
агент разбирает свободный текст и берёт требования из списка или предложений.

JSON-артефакт (`examples/architect_artifact.json`) остаётся для обратной
совместимости и автотестов.

## Выходной артефакт

Основной формат — тоже Markdown: человекочитаемый план со встроенным блоком
`CoderTask` в ```json. CoderAgent по-прежнему требует строгий JSON, поэтому
для него можно отдельно сохранить `--task-json task.json` или использовать
`--output task.json`.

## Что делает агент

1. Парсит Markdown (или JSON) и проверяет артефакт Архитектора.
2. Индексирует `front/src` и `back/src` репозитория Miminet.
3. Ищет код через гибридный Code RAG: хеш-эмбеддинги + IDF + совпадения путей
   + русско-английские подсказки + определения явно упомянутых классов/функций.
4. Формирует инструкции для CoderAgent через LLM или офлайн-эвристику.
5. Проверяет, что:
   - `modify` применяется только к найденным существующим файлам;
   - `create` не перезаписывает файл, а родительский каталог существует;
   - пути относительные, нормализованные и не выходят за репозиторий;
   - секреты, `.env`, `.git`, `.ssh` и служебные файлы запрещены;
   - каждое требование Архитектора покрыто хотя бы одной инструкцией.
6. Собирает `CoderTask` и `AnalystReport`.

Если проверка не проходит, задание Кодеру не выдаётся: CLI завершается с кодом
`1` и структурированной ошибкой.

## read_files, статусы и блокирующие вопросы

- В `read_files` попадают файлы-задания и найденный контекст (например,
  `front/src/miminet_model.py`). Кодер сможет их прочитать, но не изменить:
  запись разрешена только для `allowed_write_files`.
- `open_questions` — необязательные вопросы, которые не мешают реализации.
- `blocking_questions` — вопросы, без ответа на которые задание выполнить нельзя
  (например, в модели нет нужного поля). Если список не пуст, `AnalystReport`
  получает статус `NEEDS_CLARIFICATION`, а CLI не выдаёт `CoderTask` и
  завершается с кодом `1`.
- Если блокирующих вопросов нет, статус `READY` и задание передаётся Кодеру.

Важно: при запуске `--offline` используется детерминированная эвристика, а не
LLM. Она не понимает смысл требований, поэтому офлайн-план годится только для
проверки пайплайна и тестов, а не для реальной работы.

## Установка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ./agents/analyst
```

## Запуск

```bash
# Markdown-артефакт для человека + JSON-задание для CoderAgent
.venv/bin/python -m analyst_agent \
  --artifact agents/analyst/examples/architect_artifact.md \
  --repo ../miminet \
  --output /tmp/analyst-plan.md \
  --task-json /tmp/coder-task.json \
  --report /tmp/analyst-report.md \
  --offline
```

`--output` определяет формат по расширению: `.md` — Markdown, `.json` — строгий
`CoderTask`. `--task-json` всегда пишет JSON для CoderAgent. Без `--output`
результат печатается в stdout в Markdown (или JSON при `--format json`).
`--bundle` выводит task и report одним JSON. `--offline` не требует API-ключа
и использует детерминированный план.

## Настройки LLM

Секреты можно положить в `agents/analyst/.env` (файл в `.gitignore`):

```dotenv
OPENAI_API_KEY=...
OPENAI_BASE_URL=https://openrouter.ai/api/v1
OPENAI_MODEL=deepseek/deepseek-v4.1-flash
```

Переменные окружения имеют приоритет над `.env`. Путь к `.env` можно задать
через `ANALYST_ENV_FILE`. Поиск репозитория: `--repo`, затем `ANALYST_REPO`,
затем `MIMINET_REPO`, затем соседний `../miminet`.

## Границы ответственности

- **Делает:** анализ артефакта Архитектора, поиск по коду, проверку путей,
  формирование задания Кодеру, трассировку и тест-план.
- **Не делает:** не пишет код, не запускает тесты Miminet, не делает ревью,
  не коммитит, не пушит и не деплоит.

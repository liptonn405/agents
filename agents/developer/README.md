# Miminet DeveloperAgent — минимальный прототип

Для нового режима **CoderAgent + OpenCode**, принимающего строгий JSON-план
аналитика и запускающего редактор в OS-песочнице, см. [CODER_AGENT.md](CODER_AGENT.md).
Ниже сохранена документация отдельного legacy-режима Codex/Issue.

Скрипт превращает ручной запуск Codex в повторяемую команду. Он:

1. Получает открытую GitHub Issue из `mimi-net/miminet` **или** локальную задачу из файла.
2. Создаёт **новую ветку и изолированную Git worktree** из локальной `main`.
3. Передаёт задачу `codex exec`, давая ему возможность **редактировать только рабочую копию** в режиме `workspace-write`.
4. Собирает список изменений (включая новые файлы), запускает `git diff --check` и проверку синтаксиса изменённых Python-файлов.
5. Сохраняет машинно-читаемый `report.json`, текстовый промпт, журнал Codex и итоговое сообщение.

**Скрипт не вызывает `git commit`, `git push`, Docker, миграции или PR.** Codex получает запрет на эти операции в промпте. Для полноценного промышленного применения одного промпта недостаточно: исполнение чужого кода нужно дополнительно изолировать на уровне ОС/контейнера и проверять действия. Путь к рабочему сайту и оригинальный репозиторий в Codex не передаются.

## Требования

- Ubuntu / Linux, Python 3.10+, Git, установленный **Codex CLI**, авторизация через `codex login`.
- Локальный клон Miminet в `~/miminet` с веткой `main`.
- Для `--issue`: GitHub CLI (`gh`) в PATH, авторизация на `github.com` и доступ к API.
- Python-библиотеки отдельно устанавливать **не нужно**.
- Для unit-тестов самого Miminet могут потребоваться зависимости, которые настраиваются отдельно через `uv`.

Команда запуска проверена с `codex-cli 0.163.0`:

```bash
codex --ask-for-approval never exec --sandbox workspace-write --json --output-last-message /path/to/codex_summary.txt -
```

`--ask-for-approval` относится к корневой команде и должен стоять **перед**
`exec`: установленная версия отвергает этот флаг после подкоманды. Промпт
передаётся через stdin (`-`), рабочим каталогом процесса служит созданная worktree.
Путь `--codex-bin`, в том числе относительный, разрешается до смены рабочего каталога.

Тесты проверяют полный запуск с fake Codex, изменения файлов, stdin, журналы и
отчёт. Если `codex` доступен в PATH, дополнительный тест проверяет собранную
команду через настоящий CLI с `--help`, без обращения к модели и сети; иначе
эта проверка пропускается.

Issue получается авторизованным запросом `gh api repos/mimi-net/miminet/issues/543
--hostname github.com --method GET`. Используется существующая авторизация gh;
если её нет, выполни `gh auth login --hostname github.com`. Проверить доступ:

```bash
gh api repos/mimi-net/miminet/issues/543 --jq '.title'
```

Команда запуска агента остаётся прежней. Для `--task-file` GitHub CLI не нужен.
При отсутствии gh, проблемах авторизации, ошибке API или тайм-ауте агент
завершается с понятной ошибкой до создания worktree. Анонимного HTTP-запроса
в качестве запасного варианта нет. Авторизованные запросы также имеют лимиты:
при их исчерпании нужно дождаться сброса лимита.

Агент не извлекает токены из gh и не сохраняет его диагностический вывод.
В промпт попадают только номер, заголовок и описание Issue. Переменные
`GH_TOKEN` и `GITHUB_TOKEN` по-прежнему удаляются из окружения Codex.
Получение Issue и обработка ошибок проверяются офлайн с fake gh.

## Установка в Ubuntu

Скачай `miminet-developer-agent.zip`, распакуй его **рядом с** каталогом Miminet:

```bash
cd ~
unzip ~/Загрузки/miminet-developer-agent.zip
cd ~/miminet-developer-agent
python3 -m unittest discover -s tests -v
codex login status
```

Если файл скачался в другую папку, поправь путь. Убедись, что исходный код Miminet находится в `~/miminet`.

## Первый запуск — без Codex (рекомендуется)

```bash
cd ~/miminet-developer-agent
python3 main.py --repo ~/miminet --issue 543 --dry-run
```

Команда создаст отдельную worktree и сохранит `prompt.txt`, но **не запустит Codex**. Это проверка подготовки Git и получения Issue. После этого осмотри папку, указанную в выводе.

## Автоматический запуск агента

```bash
cd ~/miminet-developer-agent
python3 main.py --repo ~/miminet --issue 543
```

Или для другой задачи:

```bash
python3 main.py --issue 542
```

Вместо GitHub Issue можно передать текстовое описание от агента-аналитика:

```bash
python3 main.py --task-file ./my_task.md --plan-file ./analyst_plan.md
```

**Не создавай `my_task.md` внутри `~/miminet` с секретами:** весь переданный текст уходит в Codex. В рамках командного конвейера аналитик должен возвращать только сведения, нужные для исправления.

Каждый запуск создаёт **новую** worktree, например:

```text
~/miminet-agent-runs/
├── worktrees/20261022T...-issue-543-abc123.../   # изменения Codex
└── runs/20261022T...-issue-543-abc123.../
    ├── prompt.txt
    ├── codex_events.log
    ├── codex_summary.txt
    └── report.json
```

Исходная папка `~/miminet`, твоя ручная ветка `fix/543-hide-section-fields` и старая папка `~/miminet-agent-543` не меняются.

## Пример JSON-отчёта

```json
{
  "status": "NEEDS_REVIEW",
  "issue": "mimi-net/miminet#543: ...",
  "branch": "agent/issue-543-...",
  "worktree": "/home/adam/miminet-agent-runs/worktrees/...",
  "codex_exit_code": 0,
  "changed_files": ["front/src/miminet_admin.py", "front/tests/test_admin_section.py"],
  "blocked_file_changes": [],
  "checks": {"git_diff_check": "PASS", "python_syntax": "PASS"},
  "head_unchanged": true,
  "source_unchanged": true
}
```

`NEEDS_REVIEW` **не означает**, что ошибка исправлена и вся тестовая батарея прошла: это означает только успешное завершение Codex и локальных статических проверок. Смотри отдельный отчёт Codex и запускай предусмотренные проектом тесты в подходящем, **изолированном** окружении. Запуск PostgreSQL или браузерных E2E здесь намеренно не автоматизирован.

## Проверка изменённого кода

Выполни команды, подставив фактический путь рабочей копии из `report.json`:

```bash
cd /полный/путь/к/worktree
git status --short
git --no-pager diff
```

Новые файлы видны в `git status`, но обычно не отображаются в `git diff`, пока не добавлены в индекс. Их можно просмотреть через `cat` или редактор.

После ручного ревью можно сделать отдельный коммит **в агентской worktree**, но прототип не делает этого автоматически.

## Структура для интеграции с остальной командой

- `DeveloperAgent.run(issue_number=542)` — вход от оркестратора в Python.
- `DeveloperAgent.run(task_file=..., plan_file=...)` — вход от агента-аналитика.
- `RunReport` и `report.json` — выход для агента-тестировщика.
- Агент-тестировщик должен использовать путь `worktree` и собственное изолированное окружение, а не рабочую базу Miminet.

## Безопасность и ограничения

- Codex получает режим `workspace-write` и политику подтверждений `never`, то есть **не остановится для ручного подтверждения каждой допустимой команды**. Запускай его только в доверенном локальном репозитории, без секретов и без доступа к рабочим инфраструктурным ресурсам.
- Issue является недоверенным текстом. Ограничения в промпте — важная инструкция, но **не абсолютный барьер** против prompt injection и действий кода во время тестов.
- Скрипт проверяет изменение имён файлов, связанных с секретами, **после запуска**, и не делает автоматически откат. При предупреждении `POLICY_OR_CHECK_FAILURE` останови процесс, оцени изменения и при необходимости отзови ключи.
- Приоритет — контроль человеком перед любым PR и слиянием в основной репозиторий.
- Codex CLI с авторизацией через ChatGPT обычно расходует лимиты подписки; этот прототип не использует OpenAI API напрямую.
- Запуск не чистит worktree, чтобы сохранять доказательства эксперимента. Ненужные worktree удаляй позже вручную после проверки, через `git worktree remove`.

# Контракты между агентами (предлагаемая схема)

Согласуйте с архитекторами точные поля и форматы перед реализацией. Рекомендуемые сообщения:

1. `Analyst → Developer`: идентификатор задачи, описание, требования, ограничения, план, разрешённые пути.
2. `Developer → Tester`: идентификатор задачи, путь к worktree, список изменений, предварительный статус и ссылка на отчёт.
3. `Tester → Orchestrator`: статус `PASSED` / `FAILED` / `BLOCKED`, фактически запущенные проверки, логи и замечания.

Требования к контрактам: версии схем, обязательные поля, валидация путей, структурированные ошибки; не передавать токены и секреты.

**Пока эти сообщения только проектируются — существующий DeveloperAgent не обязан им соответствовать.**

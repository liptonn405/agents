# Структура командного репозитория

```text
agents/
  analyst/        # Разработчик 1: анализирует запрос, готовит план
  developer/      # Разработчик 2: выполняет план (существующий код не меняем)
  tester/         # Разработчик 3: тестирует результат
orchestrator/     # Архитекторы + команда: передача управления, лимиты попыток
shared/
  contracts/      # Единые согласованные форматы сообщений
scripts/          # Команды разработчика и проверки структуры
tests/
  integration/    # Тесты нескольких агентов вместе
docs/             # Документация для команды
```

## Правила размещения

- Код каждого агента остаётся внутри его каталога (`agents/<role>/`).
- Unit-тесты — рядом с кодом агента (`agents/<role>/tests/`).
- Интеграционные тесты всей системы — в `tests/integration/`.
- Общие форматы и независимые утилиты — в `shared/`.
- Связь между агентами и повторные попытки — в `orchestrator/`.
- Не добавляйте результаты запусков, окружения, токены или временные worktree в Git.

## Работа с ветками

Создавайте ветки от `main`: `feature/analyst-agent`, `feature/developer-agent`, `feature/tester-agent`, `feature/orchestrator`.

Изменения в `shared/` сначала согласуйте с архитекторами и остальными разработчиками.

Не отправляйте незавершённые PR непосредственно в `main`; используйте ревью и запуск тестов.

## Локальные команды

Из корня репозитория:

- `make check` — проверка структуры; если DeveloperAgent присутствует, также его unit-тесты.
- `make test-developer` — запуск unit-тестов DeveloperAgent (после его появления в текущей ветке).
